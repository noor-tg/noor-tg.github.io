Deploys in four minutes: what we cut

Most of our 40-minute deploy was waiting. Here is how we found it and removed it.

When I joined Lumen, a deploy took forty minutes. Nobody thought it was slow, because everybody had stopped watching it. The first thing I did was print a timeline of every step and who waited for whom.

Find the waiting

Only eleven of those forty minutes were real work. The rest was cold caches, tests that ran one after another and an image that was rebuilt from scratch every time.

# before: serial
build -> test -> package -> push -> deploy

# after: parallel + cached
build ─┬─ test:unit
       ├─ test:api
       └─ package ─> push ─> deploy

Make the fast path the default

We ran tests in parallel, cached dependencies by lockfile hash and only rebuilt the layers that changed. Four minutes later we stopped talking about deploys at all, which is the best result a deploy can have.
