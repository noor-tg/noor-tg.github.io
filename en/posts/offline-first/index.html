Offline-first without the pain

A practical pattern for syncing edits with SQLite, taken from the Roam app.

Offline-first sounds like a feature, but it is really a decision about where the truth lives. In Roam the truth lives on the phone, and the server is just a very good backup.

Store operations, not states

Instead of saving the latest itinerary, we save what the person did: add a stop, move a stop, rename a day. When the phone reconnects it replays that list, and the server merges the lists from every device.

CREATE TABLE ops (
  id TEXT PRIMARY KEY,
  kind TEXT NOT NULL,
  payload JSON NOT NULL,
  created_at INTEGER NOT NULL,
  synced INTEGER DEFAULT 0
);

Make conflicts boring

Most conflicts are two people changing different things. Merging operations makes those disappear. For the few real ones we show both versions and let the person choose, because a clear question beats a clever guess.
